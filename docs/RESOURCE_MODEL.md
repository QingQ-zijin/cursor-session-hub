# 解析与资源模型

会话读取分为发现、后台索引、已发布版本读取。HTTP阅读、搜索、评论不调用原始Cursor解析器。原始JSONL按行有界读取，SQLite仅复制选中会话的composer/bubbles和被引用内容；每个worker只运行一个子进程。

正文事件以小预览写入数据库，完整内容写入磁盘并通过opaquecontentID分段读取。每200事件或1MiB提交检查点，版本完成后原子发布。异常记录保留raw诊断与原始字节。CLI工具结果和IDE孤立消息恢复使用临时SQLite连接和查询，避免整会话dict及两两内存比对。

默认单记录8MiB上限、每次内容256KiB、事件页40条且总量≤1MiB；请求队列50/每成员10；上传4MiB分块，2个全局/每成员1个。worker进程树RSS达到512MiB预算的90%时终止并保留检查点。Docker再施加1CPU/512MiB硬限制。

UI默认最近3轮、最多3轮展开；轮目录和会话目录分页，工具和图片点击加载。图片源文件不从任意服务器路径读取，只能访问关联且授权的assetID。

中文搜索使用CJK单字/双字与英文词索引；短中文词可检索，不依赖大模型。未提交的新版本不参与正常搜索。长导出和同步包由后台worker流式生成。

重复源内容不重建；源文件追加确认前缀不变后复用已提交记录；截断/改写新建版本。旧评论始终绑定旧版本与消息，绝不自动漂移。

运行 `python tests/stress_ingest.py --help` 查看可复现压力测试参数。测试文件和指标存入 `.runtime`，不提交真实会话。
