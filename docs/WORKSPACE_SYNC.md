# 工作区批次同步

本地工作区列表的「同步全部工作区」可一次创建全部工作区的同步批次。工作区标题旁的云图标同步整个工作区，不受当前页只显示 50 条记录的限制。来源窗口中也提供同样的操作。

默认目标为本地库，免登录。来源窗口的「同步目标」可切换为团队服务器并记住选择；服务器模式要求先登录团队空间，批次会先逐条解析到本地库，再逐条上传。上传包含会话记录和明确关联的图片，不上传整个 Cursor 全局数据库或项目目录。未命名和其他来源默认折叠，仍可以手动展开选择。

## 范围

- 优先读取当前 Cursor Agents 界面的工作区目录、成员映射和 `composerHeaders`，兼容旧版工作区的 `allComposers` 目录；不会仅凭文件夹路径把所有缓存当作左栏会话。
- 同步全部工作区：选取左栏已命名的独立会话，排除未命名、已归档和内部子代理；同一个会话优先使用 IDE 来源，JSONL 副本不重复处理。
- 同步单个工作区：包含该工作区下的全部独立会话，包括尚未命名的独立会话；内部子代理不会作为独立会话再次导入。
- 空工作区仍可显示。同步采用新增/更新方式，不主动删除之前导入的其他记录，也不自动撤销已有云端共享。
- 未识别目录时报告失败并保留手动导入入口；不会悄悄把所有历史缓存上传。

## 资源和恢复

批次清单持久化到数据库，后台协调器一次只投放一个普通解析或同步任务。批次可超过 10 条、跨越多页，但普通任务队列和单解析进程的资源限制保留。正文、图片和大块内容继续分段读取。

关闭来源窗口不影响任务执行；退出应用后进度保留，下次启动继续处理。可在来源窗口或任务页面查看进度、暂停、继续、取消，以及重试失败项。取消后不自动重新上传；完整失败明细按 50 条分页。

本版为单机一个活动批次。启动后会先扫描并固定清单，批次进行中「发现记录」复用该扫描，避免重复扫描改变批次范围。服务器账号或地址发生变化时，原批次不会悄悄切换到另一个账号；需要按错误提示重新创建。

## 最终回答阅读

每轮根据最后一个明确的工具调用分界：用户问题保持可见；分界前的助手说明、思考和执行记录默认折叠；分界后的全部回答段落保持展开。同一条消息内混合文字和工具时，也会按内容块分开。

纯文字记录缺乏工具边界时保留完整文字，不猜测哪一段应该丢掉。若没有记录执行后的回答，会显示提示并保留过程入口。超大或未知结构仍可读取完整记录，折叠只影响展示，不改变原始内容、导出或同步。

升级采用 schema version 4 加表迁移，现有本地记录、标题、收藏、回收站和登录凭证保留。
