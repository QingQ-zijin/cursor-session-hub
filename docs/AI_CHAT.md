# API 聊天

管理员在聊天框右上角齿轮或团队成员管理中的「团队 API 设置」填写 Base URL、API Key 和模型名称，再启用 API。支持 OpenAI 兼容的 `/chat/completions` 接口；Base URL 通常包含 `/v1`，不要重复填写 `/chat/completions`。不内置付费模型或密钥，服务商费用由其账号承担。

本地空间和团队空间分别配置。本地密钥使用操作系统凭证存储中的主密钥加密；团队密钥加密保存在服务器数据库，解密主密钥位于数据目录 `ai-master.key`，不会返回成员客户端。团队管理员才能改配置；普通成员可以使用已启用的团队模型。更换服务地址必须重新填写密钥。

打开已解析会话后，下方聊天框默认引用当前版本。输入 `@` 或点击引用按钮可选择其他会话，最多五个；发送前可移除引用。首页 New Chat 也可以独立聊天或引用选中的会话。Enter 发送，Shift+Enter 换行；停止按钮结束当前生成。聊天记录按账号私有保存，独立于原始 Cursor 记录，不会写回 Cursor 或改动同步历史。切换设备只会看到同一服务器、同一账号的团队聊天；本地聊天留在本机。

## 长会话与资源

- 引用只访问磁盘索引，按提问关键词及近期消息选择片段，不重新解析原文件。默认引用预算 24,000 字符，管理员可设 4,000–64,000；界面明确显示片段引用，不声称读完全部历史。
- 不发送图片或原始项目文件；工具记录作为参考文字，历史指令不作为系统指令，没有工具执行能力。
- 当前聊天最多使用最近 20 条已完成消息，历史文本总预算 12,000 字符；每条历史消息可能截取。新问题最多 8,000 字符。
- 每成员同时一个生成请求，全服务最多两个，与单任务解析队列分开。默认输出 2,048 token，可设 128–8,192；本地保存单条回复最多 64,000 字符。
- 流式读取限制、网络超时和生成超时会保留已收到文字并显示原因。浏览器连接中断后只续读回复，绝不自动重新提交付费模型请求。服务重启时未完成生成标为中断，由用户决定是否重发。
- 生产部署保持一个 API 进程/副本；聊天准入、启动恢复按此拓扑设计。不要直接扩展多个 API 实例。

## 升级和备份

1.5.1 启动时进行加表迁移（schema version 2），增加 `ai_settings`、`ai_threads`、`ai_messages`，不重写原有会话。现有全量备份脚本同时保存数据库和数据卷，因此包含服务器主密钥。恢复时必须同时恢复两者；单独恢复数据库无法解密 API Key。迁移本地应用数据到另一台电脑后需重新配置 API Key，因为系统凭证存储不会随文件复制。

接口兼容性通过不计费的本机 HTTP 模型测试服务验证；具体服务商仍需管理员填写密钥后实际试用。原生 Anthropic Messages 协议不包含在本版，可使用提供 OpenAI 兼容协议的网关。
